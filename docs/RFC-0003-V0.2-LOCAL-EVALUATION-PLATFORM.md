# RFC-0003: v0.2 Local Evaluation Platform Contract

- **Status:** Proposed; the TwinBundle/scripted Episode subset is accepted by
  ADR-0018, the durable Journal subset by ADR-0019, and the fenced remote
  coordinator subset by ADR-0020
- **Created:** 2026-08-26
- **Target:** v0.2 development line
- **Authority:** subordinate to accepted ADRs and RFC-0002 for stable v0.1
- **Normative language:** RFC 2119 / RFC 8174

## 1. Decision

MCP State Twin remains a deterministic world and evidence substrate for
tool-using agents. It does not become an agent loop, model host, memory system,
coding sandbox, or production-service proxy.

The v0.2 product direction adds a portable local evaluation boundary above the
existing L1 runtime:

```text
TwinBundle
  -> admission and digest verification
  -> one isolated scripted EvaluationEpisode
  -> existing Scenario runner and deterministic world
  -> EpisodeEvidence with terminal-state report
```

This RFC is broader than the currently accepted implementation. ADR-0018
accepts only the bounded, synthetic, local and scripted subset named there.

## 2. Product boundary

The project owns:

- deterministic modeled world state;
- TwinSpec transitions and invariants;
- snapshots and isolated branches;
- modeled time and fault profiles;
- evaluation artifacts and terminal-state evidence; and
- host compatibility evidence admission.

The project does not own:

- model inference or reasoning;
- conversation state or context compaction;
- agent planning or orchestration;
- coding-workspace sandboxing;
- provider approval UX;
- real upstream service semantics; or
- an unrestricted remote multi-tenant control plane.

## 3. New hard invariants

### ST-V2-I11 Episode isolation

Every model-driven trial MUST use an independent branch, provider thread and
evidence namespace. The accepted local scripted subset uses a fresh in-memory
store per invocation.

### ST-V2-I12 Artifact closure

Every non-secret input required by a portable local run MUST be named and
digested by one TwinBundle. Environment variables, mutable URLs and undeclared
local files are not portable evaluation inputs.

### ST-V2-I13 Claim derivation

A Bundle verification or Episode evidence document proves only its declared
local artifact/runtime result. It MUST NOT be converted into a provider,
fidelity or production-readiness claim.

### ST-V2-I14 No hidden surface projection

Future host adapters MUST record any change to tool names, descriptions,
schemas, annotations or error presentation. The current local scripted Episode
has no host projection and remains `scripted-scenario`.

### ST-V2-I15 Evidence-preserving ambiguity

Cancellation, response loss and provider failure MUST preserve whether a world
transition committed, did not commit, or is unknown. These remote/provider
semantics are not implemented by the accepted local subset.

### ST-V2-I16 Versioned contracts

TwinBundle and EpisodeEvidence have independent format identifiers. A future
incompatible field or digest change requires a new format version and migration
or explicit refusal.

## 4. TwinBundle v1alpha1

The accepted source manifest is:

```yaml
apiVersion: statetwin.dev/v1alpha1
kind: TwinBundle
format: statetwin.dev/twin-bundle/v1alpha1
metadata:
  name: issue-tracker-smoke
  version: 0.2.0-alpha.1
spec: twin.yaml
fixture: state.json
scenarios:
  - scenario-close-issue.yaml
```

The source manifest MUST omit digests. `statetwin bundle build` reads only
declared members below the manifest directory, computes every SHA-256 digest,
generates the archive manifest and writes a deterministic ZIP artifact.

### 4.1 Admission

The implementation MUST:

- reject unknown manifest fields, multiple YAML documents, aliases, anchors
  and explicit tags;
- reject absolute paths, backslashes, empty segments, `.` and `..` traversal;
- reject symlinks and non-regular files;
- reject duplicate archive names and undeclared archive members;
- bind exactly one TwinSpec, one fixture and at least one Scenario;
- limit the archive to 128 files, 32 MiB compressed, 64 MiB extracted and
  16 MiB per member;
- verify every member digest before use; and
- produce byte-identical archives for byte-identical declared inputs.

The format does not support executable code, native libraries, remote
references, provider credentials, signatures or recorder traces.

### 4.2 Identity

`TwinBundle.digest` is SHA-256 over the deterministic archive bytes. Member
digests are SHA-256 over exact member bytes. Compression format and archive
metadata are therefore part of v1alpha1 bundle identity; a future format may
define a transport-independent bundle identity separately.

## 5. Local EvaluationEpisode subset

`statetwin episode run` executes one declared Scenario from one verified
TwinBundle. It is deliberately not a live model harness.

The lifecycle is:

```text
CREATED -> PROVISIONING -> READY -> RUNNING -> EVALUATING
                                              |-> SUCCEEDED
                                              `-> ASSERTION_FAILED
```

The state machine also defines `RUNTIME_ERROR` and `CANCELLED`, but the current
single-process command returns an operational error rather than persisting a
partial Episode record when provisioning/runtime construction fails.

Requirements:

- Episode IDs MUST match `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`;
- a requested Scenario MUST appear in the Bundle manifest;
- omitting `--scenario` is allowed only for a one-Scenario Bundle;
- the fixture is strict, bounded JSON in the existing world-state schema;
- execution MUST reuse the same Scenario/runtime path as repository tests;
- assertions and terminal state remain the correctness oracle;
- the evidence claim level is `development`;
- agent identity remains `scripted-scenario`; and
- a development binary records revision `unknown` unless build metadata injects
  an immutable revision.

Without `--journal`, this local lifecycle is not durable across process exit.
Neither mode implements remote retries, provider threads or cancellation.

### 5.1 Durable local Journal amendment

ADR-0019 adds an optional independent SQLite Journal. With `--journal`, Episode
creation and lifecycle transitions are durable, an immutable request digest
provides idempotent terminal replay, and `episode inspect` exposes the persisted
record. Existing non-terminal records fail explicitly as `incomplete`; they are
not resumed or retried. This is persistence, not crash-safe provider recovery.

## 6. EpisodeEvidence v1alpha1

The evidence envelope contains:

- Bundle digest;
- Episode ID;
- selected Scenario path;
- runtime semantic version and build revision;
- ordered lifecycle transitions;
- outcome;
- deterministic Scenario report; and
- canonical evidence digest.

The embedded Scenario report remains synthetic-only and may contain tool inputs
and results. Evidence output files are created through a temporary file,
synced, given owner-only permissions where supported, and atomically renamed.
Operators MUST still perform the repository secret/fixture policy before
publishing evidence.

## 7. Resource profile

ADR-0018 amends ADR-0013 by enabling only TwinBundle limits:

| Limit | Value |
|---|---:|
| files | 128 |
| compressed bytes | 32 MiB |
| extracted bytes | 64 MiB |
| member bytes | 16 MiB |

ADR-0019 adds a 10,000-record local Episode Journal limit and advanced the
resource profile to `local-preview-v3`. ADR-0020 subsequently advances it to
`local-preview-v4`, with 16 attempts per Episode task and a 3,600-second lease
bound. ADR-0026 through ADR-0028 advance it to `local-preview-v5` with bounded
modeled entropy and a private opaque-signal scheduler. Its digest therefore
changes and remains part of Scenario environment identity. Cassette and future
task limits remain zero; scheduled tool/Agent effects remain disabled.

## 8. CLI contract

The accepted commands are:

```text
statetwin bundle build --manifest bundle.yaml --out twin.stb
statetwin bundle verify --bundle twin.stb
statetwin episode run --bundle twin.stb --id run-001 [--scenario path] [--out evidence.json]
statetwin episode run --bundle twin.stb --id run-001 --journal episodes.db
statetwin episode inspect --journal episodes.db --id run-001
```

Their successful stdout is structured JSON with `apiVersion` and `kind`.
Existing v0.1 commands remain unchanged. Stable global output modes and the
expanded exit-code taxonomy proposed for v0.2 are not accepted by ADR-0018.

## 9. Security boundary

The accepted subset performs no network calls and imports no provider SDK. It
does not add authentication, TLS, multi-tenancy, upstream discovery, recorder
or passthrough code. A Bundle cannot expand the MCP/control surface or inject a
script.

Bundle integrity is not publisher authenticity. Signatures, SBOM linkage,
provenance and a trusted registry require a future ADR.

## 10. Deferred v0.2 components

The following remain proposal work:

- automatic Episode retry/resume, cancellation and ambiguous-commit recovery;
- `/control/v1/episodes` and authenticated Episode-scoped MCP URLs;
- HostProfile and HostSurfaceProjection parsers;
- live Codex/OpenAI/ChatGPT/Claude harnesses;
- evidence-derived compatibility matrix generation;
- canonical state export/import;
- signed Bundle/evidence attestations;
- OpenTelemetry events and diagnostics bundles;
- remote security and multi-tenant quotas;
- recorder/L0 and L2 differential fidelity; and
- the complete stable CLI/exit-code redesign.

## 11. Acceptance evidence for ADR-0018

- deterministic Bundle build test;
- path traversal, unknown-field and caller-supplied-digest refusal tests;
- undeclared member and digest-tamper refusal;
- local Episode lifecycle transition tests;
- bundled issue-tracker Episode deterministic evidence test;
- invalid Episode ID and undeclared Scenario refusal;
- CLI smoke for build, verify and Episode execution; and
- hermetic and release workflow smoke steps, with actual pass/fail recorded by
  the public CI run for the candidate commit.

ADR-0019 additionally requires:

- Journal close/reopen with intact terminal Evidence;
- identical-request idempotent replay without a second lifecycle;
- same-ID/different-request conflict;
- explicit refusal to rerun a non-terminal incomplete record;
- runtime-error records without raw error text;
- request, lifecycle and Evidence tamper refusal;
- foreign and future SQLite schema refusal; and
- hermetic/release CLI smoke for `--journal` and `episode inspect`.

## 12. Stable release interaction

These features are preview extensions outside the stable v0.1 support claim.
They do not close or add a substitute for RFC-0002's live OpenAI-family and
Anthropic-family provider-smoke gate. They also do not authorize a stable
`v0.1.0` tag while that external evidence remains absent.
