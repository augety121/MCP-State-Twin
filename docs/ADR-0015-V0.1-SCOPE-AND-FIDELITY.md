# ADR-0015: Accept the v0.1 L1-Only Release Profile

- **Status:** Accepted
- **Date:** 2026-08-24
- **Decision owners:** repository maintainers
- **Amends:** RFC-0001 section 6 and section 27
- **Accepts:** RFC-0002 as the authoritative v0.1 release profile

## Context

RFC-0001 originally placed L0 cassette replay and the L1 stateful runtime in
the same v0.1 milestone. Recorder/replay introduces a different security and
legal boundary: redaction, consent, incomplete traces, authorization material,
and upstream network access. L2 fidelity likewise requires upstream
differential evidence that is independent of a correct L1 runtime.

Keeping these unrelated capabilities in the first stable milestone creates an
incentive to add an unsafe recorder or make an unsupported fidelity claim.

## Decision

The stable v0.1 profile is limited to the local, hermetic, deterministic **L1
stateful runtime** defined by RFC-0002.

The following are explicitly outside the stable v0.1 support claim:

- recorder and L0 cassette replay;
- upstream network inspection or passthrough;
- automatic fidelity promotion;
- L2 differential validation and L3/native adapters; and
- provider/model behavior guarantees.

Absence is part of the v0.1 safety case. If recorder, upstream access, L2
promotion, or native adapters enter the release branch, their previously
excluded failure modes become active blockers immediately.

## Required public wording

The project may claim a synthetic `L1/unverified/unbound` stateful Twin. It must
not claim L2/L3 fidelity, production equivalence, provider compatibility, or
recorder/replay support without separate accepted decisions and executable
evidence.

## Consequences

- RFC-0002 becomes Accepted and wins over the older RFC-0001 milestone text.
- The recorder/L0 release gate is satisfied by explicit exclusion, not by
  implementation.
- P0 F-010 is satisfied for v0.1 because L2 is excluded and L1 is labeled
  accurately; the future L2 promotion workflow remains open work.
- This ADR does not remove provider smoke, storage recovery, HTTP, migration,
  conformance, or documentation gates from RFC-0002.
