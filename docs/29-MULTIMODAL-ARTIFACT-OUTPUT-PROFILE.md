# Multimodal & Artifact Output Profile

> **Status:** Future-capability Proposal / Unverified  
> **Purpose:** Prepare State Twin for agents whose tool results include files, images, audio or other non-trivial artifacts.

## 1. Scope

The current project is primarily a structured tool/state runtime.

Future hosts may consume richer MCP result content.

This profile defines architecture boundaries without requiring v0.1 support.

## 2. Artifact identity

An artifact should have:

```yaml
artifact:
  id: ...
  mediaType: ...
  byteLength: ...
  digest: sha256:...
  storageClass: inline|managed-file|external-reference
  redactionClass: ...
```

## 3. Canonical world state

Large binary content SHOULD NOT be embedded directly into canonical JSON world state.

Prefer:
- content-addressed artifact store;
- canonical metadata/reference in world state.

## 4. Determinism

For deterministic artifacts:
- generated bytes or source artifact digest must be reproducible;
- image/audio metadata that embeds host timestamps/random IDs must be normalized or explicitly excluded from deterministic identity.

## 5. Host transforms

Hosts may:
- inline content;
- save to file;
- truncate;
- show preview;
- strip unsupported media;
- convert format.

Evidence stores:
- canonical artifact digest;
- raw MCP content metadata;
- host-visible transform.

## 6. Security

Artifacts require:
- MIME validation;
- size limits;
- filename/path sanitization;
- no executable auto-launch;
- archive bomb protection;
- secret/PII classification.

## 7. Scenario scoring

If the task is state-based, score world state.

If artifact content itself is the target:
- use explicit artifact assertions;
- digest/exact match when deterministic;
- bounded semantic evaluator only if the evaluation methodology defines it.

## 8. Feasibility

**Medium-high**.

The storage/evidence mechanics are straightforward. High-fidelity multimodal semantic scoring is domain-dependent.
